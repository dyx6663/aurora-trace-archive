AURORA TRACE：证据驱动的本地编程智能体

Git 仓库地址：https://github.com/dyx6663/aurora-trace

一、运行方法
需要 Python 3.10+。进入项目目录后执行：
python aurora.py
浏览器访问 http://127.0.0.1:8765，选择项目和任务即可运行。项目支持通过环境变量配置 OpenAI 兼容模型接口；API 凭据不会写入项目文件或运行记录。

二、设计思路与特色
AURORA TRACE 面向软件工程任务，重点解决“Agent 改了什么、依据是什么、结果是否可信”难以复查的问题。项目未使用 LangChain、LlamaIndex、Agents SDK 等 Agent 框架，模型交互、上下文管理、工具定义与解析、执行循环、错误处理和终止条件均自行实现。

核心设计是 Evidence Ledger：将模型决策、工具输入、本地执行结果、代码 Diff 与测试证据按因果关系组织起来，形成可追溯、可回放的运行记录。Agent 在隔离工作区中执行，文件访问受边界限制，命令执行采用白名单、超时和非 Shell 调用。

项目还引入任务感知的验收契约：Bug 修复要求先复现修改前失败，功能新增、结构重构和一般变更则先确认绿色基线；不同任务使用相应的验证条件。只有真实测试和所需证据全部通过，程序才允许结束，模型不能自行宣布成功。模型、工具执行器和验证器彼此分离，使“行动—执行—验证—记录”形成可解释的闭环。

三、其它说明
运行支持人工审批、协作式取消、运行历史和事件回放。项目定位是可复现的工程实验平台，不宣称提供生产级沙箱或通用多智能体调度。
